## 二、问题与动机

### 2.1 现有方法的共同建模简化

从点云构建可通行地表、再做拓扑抽象与分层规划，这条技术线（mesh navigation、elevation mapping + 栅格搜索、navmesh 类方法）普遍把机器人近似为**圆盘**：用一个标量半径或标量通行宽度判断某处能否通过。

该近似在窄通道处同时产生两类错误，且二者不可兼得：

- **假阻断（false blockage）**：以外接圆半径为判据，斜向可通过的通道被判为不可通行。后果是地图连通性丢失，本来可达的区域变为不可达，规划器返回"无路"。
- **假通行（false traversal）**：以内切圆半径为判据，几何上无可行朝向的通道被判为可通行。后果是规划器返回的路径在执行阶段碰撞或卡死。

对矩形足迹机器人，二者之间不存在"取中间值"的正确解：能否通过本质上取决于**接近角**，是一个朝向上的可行区间问题，不是一个标量阈值问题。

### 2.2 本工程中的直接证据

当前 `topmap_ws` 实现完整复现了这一简化，可作为论文中"问题确实存在"的第一手材料：

- `RobotParams::length = 0.80` 在全代码库中仅被 YAML 解析（`params.cpp:99`）、合法性校验（`params.cpp:195`）与地图归档读写（`map_archive.cpp:270,426`）触及，**未参与任何一次几何计算**。
- 所有可通行性判据归约为两个标量：`required_clearance() = 0.5*width + safety_distance = 0.45`、`required_width() = width + 2*safety_distance = 0.90`。即把 0.60 × 0.80 的矩形机器人当作直径 0.60 的圆盘。
- `TraversabilityEvaluator`、`PortalValidator`、`SurfaceAStar`、`SafetyValidator` 全链路无 yaw 维度（全库 grep 无 `yaw` / `orientation` / `footprint` 的几何用法）。
- 当前取 `0.5*width` 作为 clearance 判据，属于**内切圆侧**，即系统性偏向假通行：规划器可能返回实际执行不了的路径。

### 2.3 为什么这是一个值得做的问题

把标量宽度升级为朝向区间，看似只是增加一个维度，实际改变了问题的性质：地图的连通性本身变成**与机器人朝向耦合**的量。由此带来三个新的研究问题：

1. 单个 Portal 的可行朝向集合如何刻画与计算；
2. 相邻两个受约束 Portal 之间的朝向耦合（进入朝向 → 离开朝向）如何在 Region 内部判定；
3. 拓扑压缩在新的可达性定义下需要什么不变量——旧的位置可达性不变量不再充分。

## 三、创新点

### 贡献一：朝向可行区间标注的地图表达（主贡献）

**Portal 升级。** Portal 的通行判据从标量 `valid_width > required_width()` 升级为**可行 yaw 区间并集**。给定边界链与局部切平面，矩形足迹能够穿越该 Portal 的朝向集合是若干闭区间的并——每条约束边界给出一个区间，取交集即得，可解析求解，无需朝向采样。

Portal 由此分为三类：

- 自由通行：任意 yaw 可过；
- 受约束通行：yaw 属于一个区间并集（通常 1–3 个区间）；
- 不可通行。

**Region 升级。** Region 增加旋转可达性属性。若 Region 内存在半径等于足迹外接圆的自由球，则旋转完全自由；否则旋转只能沿受限走廊进行，可行的"进入朝向 → 离开朝向"关系是区间上的一个可达关系，离线计算并随地图归档。

两项标注均在离线建图阶段完成，在线规划零额外几何开销。

### 贡献二：提升图上的分层规划与归约定理

Topology A* 的节点由 Region 升级为 (Region, 可行朝向区间) 的笛卡尔积。由于每个 Region 的区间数通常为 1–3，图规模仅放大常数倍，现有分层规划的效率优势完整保留。

**核心命题（归约的双向正确性）：** 提升图上存在路径，当且仅当曲面 SE(2) 配置空间中存在可行路径。

两个方向分开陈述、分开证明：

- **可靠性（soundness，无条件）**：提升图上任一路径均对应一条实际可执行的曲面路径，即假通行率为 0；
- **完备性（completeness，条件性）**：在明确给出的区间离散化与 Region 旋转充分性条件下，若存在可行路径则提升图上必然存在对应路径，即假阻断率为 0。

该命题是把本工作从"工程系统"抬升为"方法"的关键。缺少它，工作只能投会议或低区期刊；有了它，"将高维连续规划问题可靠且完备地归约为常数倍放大的图搜索"构成审稿人认可的方法层贡献。

### 贡献三：朝向感知的拓扑压缩不变量

现有 `TopologyInvariants::sameConnectivity` 保持的是位置可达性、连通分量数与 cycle_rank。引入朝向后可构造如下反例：

> 一次 Region 合并保持了位置可达性、连通分量数与 cycle_rank，却破坏了 SE(2) 可达性——被合并掉的中间 Region 正是为两个受约束 Portal 之间提供旋转空间的那一块。

因此 `nonContractibleRegions` 必须新增"旋转瓶颈"类别，压缩不变量需要从位置可达性推广到朝向耦合可达性。该反例可作图、可做消融、可独立成节，并直接论证现有不变量的不充分性。

## 四、技术路线与阶段划分

### 阶段 0：可行性判定（kill gate，优先级最高）

**目标：** 用数据而非判断决定这篇论文是否存在。

在现有 8 个合成场景之外，补充若干专门设计的斜向窄通道场景，用解析方法计算矩形足迹的可行 yaw 区间，统计两个数：

- 外接圆基线的**假阻断**通道数；
- 内切圆基线（即现有 `0.5*width` 判据）的**假通行**通道数。

**判定准则：** 若在目标真实场景中两数均接近零，整个故事不成立，立即转向备选方向，沉没成本仅数日。若显著非零，进入阶段 1。

**配套动作：** 同期完成文献排查（见第八节），这是本路线最大的单点风险。

### 阶段 1：把 robot_length 接入几何（1–2 周）

实现 Portal 的 yaw 区间解析计算与 Region 旋转可达性，结果写入 `map_archive`（归档版本号须升级，并保留旧版本拒绝加载的结构化报错）。

本阶段**不改规划器**，只观测地图层面的连通性变化：多少通道由"死"转"活"，多少由"活"转"死"。这是贡献一的独立可验证产出。

### 阶段 2：提升图规划与定理（2–3 周）

扩展 Topology A* 至提升图，完整保留现有各级回退路径（corridor 扩张、full-mesh 回退、平滑失败回退）。

**定理证明在本阶段完成，不留到最后。** 写证明的过程会暴露建模漏洞——最典型的是 Region 内旋转充分性条件（外接圆自由球是充分条件而非必要条件），此时修改建模仍来得及。

### 阶段 3：数据与基线（与阶段 0 并行启动，周期最长）

这是当前距离 1 区最远的一环，必须尽早启动：

- **自采真实数据**：用已有的 `lio_sam_hesai` 采集多层停车场 / 多层厂房，产出 `GroundMap.pcd`，目标 10^6–10^7 点量级。当前 benchmark 最大仅 20320 个三角面，该量级在 1 区会被直接质疑。
- **公开数据集**：补 1–2 个含多层结构的公开序列（Hilti SLAM Challenge、M2DGR 一类值得排查，但其多层地面覆盖是否足够需自行核实）。
- **已发表基线**：必须包含他人发表的系统，仅与自实现的 `mesh` / `point_cloud` 朴素基线对比是常见拒稿理由。建议至少三条：mesh navigation（Putz 等）、elevation mapping + 栅格 A*、OMPL 曲面投影的 SE(2) 采样规划器（作为"完备但慢"的上界参照）。

**附带收益：** 数据规模上去后，分层规划的加速比会从当前 1.6 倍量级提升到一到两个数量级，辅助结果自然变好。

### 阶段 4：执行验证（3–4 周）

"假通行率为 0"是本工作最硬的主张，必须有执行数据支撑，不能只有几何证明。

真机优先（现有 Jetson 平台 + 既有 SLAM 栈具备条件）；若真机不可行，在 Gazebo / Isaac 中部署真实尺寸的矩形差速底盘与控制器，统计实际执行成功率。

## 五、评价指标口径

**主结果（三个相互正交的量，基线上均显著非零，本方法归零）：**

1. **假阻断率**：外接圆基线判为不可通行、而实际存在可行 yaw 的通道比例。本方法在此恢复连通性，直接对应"地图上本来到不了的区域现在到得了"。
2. **执行失败率**：内切圆基线返回、而机器人实际执行时碰撞或卡死的路径比例。本方法应为 0。
3. **压缩后 SE(2) 可达性保持率**：旧不变量下非零失效，新不变量下 100%。

**辅助结果（降级为次要）：** 展开节点数、规划时间、路径长度劣化比、地图压缩率。

当前 benchmark 的 mesh 8722 对 hierarchical 6671 这一量级作为论文主结果过弱，必须让位给上述三个指标。

## 七、必须主动声明的适用边界

以下两点在论文中主动写明，不等审稿人指出：

1. **底盘模型限制**：矩形足迹 + 原地旋转的假设对差速驱动贴合（"Region 内旋转可达性"这一建模正依赖该前提），对 Ackermann 底盘不成立。
2. **完备性的条件性**：区间离散化下的完备性是有条件的完备性，条件须明确列出，不得含糊表述为"完备"。

## 八、风险与应对

**风险一：文献抢先（最大单点风险）**

非圆形足迹的 SE(2) 规划（state lattice、footprint-aware costmap）、navmesh 的 clearance 建模（Geraerts 的 ECM 一类）、采样规划中的窄通道识别，均有大量既有工作。本工作的新颖性依赖于"三维多层地表 + Region-Portal 抽象 + 解析朝向区间 + 归约定理"这一特定组合，而非任一单独组件。

**应对：** 阶段 0 内完成系统性文献排查，覆盖 mesh navigation、navmesh / ECM、state lattice、以及 SE(2) 窄通道三个方向。若发现强抢先，优先考虑重新定位（例如把重心移到贡献三的压缩不变量，该点最独特）而非放弃。

**风险二：效应量不足**

若真实场景中通道普遍远宽于 `required_width()`，两类错误率接近零，贡献一失去意义。

**应对：** 阶段 0 即为该风险的闸门。注意效应量与机器人尺寸、环境尺度之比强相关：若目标平台为大尺寸工业 AGV（而非 0.60 × 0.80 的小车），窄通道占比显著上升。平台选择须由真实应用场景支撑，不得为凑效应量而人为放大足迹。

**风险三：定理弱化**

Region 内旋转的必要条件可能难以刻画，定理可能退化为"无条件可靠 + 较强假设下完备"。

**应对：** 该弱化形式仍可发表（第三梯队稳妥、第二梯队可争）。关键是在阶段 2 尽早发现并据此调整投稿目标，而非在投稿后被动降级。

**风险四：实验工程量**

真实数据采集、三条已发表基线复现、真机验证构成本路线主要工作量，属资源与时间问题而非不确定性。

**应对：** 阶段 3 与阶段 0 并行启动；基线复现可按"必需三条"的优先级顺序推进，OMPL 参照基线可最后补。

## 九、与现有工程的关系

现有模块全部保留，朝向标注是叠加的一层：

- 不改动：region growing、三路 Region 分裂、Portal 提取、分层规划器骨架、各级回退逻辑、现有全部单元测试；
- 扩展：`Portal` 结构体增加 yaw 区间字段，`SurfaceRegion` 增加旋转可达性字段，`PortalValidator` 增加区间计算，`TopologyAStar` 升级为提升图搜索，`TopologyInvariants::nonContractibleRegions` 增加旋转瓶颈类别；
- 升级：`map_archive` 版本号，并保持旧版本结构化拒绝加载的既有行为。

工程风险低。那个一直未参与计算的 `robot.length`，由此成为核心参数。

## 十、备选方向

以下两项可作为后续工作或并列贡献，不建议作为首篇主创新点：

**增量式拓扑保持更新。** 局部地图变化下的 Region-Portal 图局部修复，带不变量证书与有界重算量。有理论抓手（T-ASE / RA-L 量级），但现有设计文档明确将在线增量更新排除在范围外，架构改动较大，且需要地图变化序列数据。适合作为第二篇。

**不确定性 / 风险感知 Portal。** 可通行性建模为分布，Portal 带通过概率，CVaR 约束下规划。可发表，但需噪声建模与真实传感数据，且该方向正在变得拥挤。可作为第三个贡献点挂载。
